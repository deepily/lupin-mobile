## 1. Problem (founding incident, 2026-06-12 ~01:10–03:45 EDT)

During a fleet-wide Max-plan quota freeze, a worker seat (Tiffany 💍, session 472b7468) parked
at the Claude Code rate-limit dialog. The dialog blocks everything — including a memento write.
Recovery required injecting a keystroke into the worker's tmux pane; the permission classifier
DENIED the manager's injection twice. The second denial was principled: it could not verify that
the manager's `ask_yes_no` "yes" was a live human answer rather than a timeout default. The seat
was lost and replaced via reap-and-takeover (worked, but cost a rotation and the seat's
in-flight context).

Root cause framing (postgame consensus): **the classifier was correctly conservative; the gap is
the missing first-class recovery primitive**, not the block. Standing keystroke-injection
permission for managers (a Bash allowlist rule) was considered and REJECTED — widest blast
radius on the table, and the timeout-default ambiguity stays unsolved. Related doctrine:
manager-autonomy.md §8 rule 3 (non-launderable authorization).

## 3. Requirements

**R1 — Detection.** The cosa-voice listener (host-side; already tracks every CC session's tmux
pane + session bridge) recognizes the rate-limit dialog signature in a pane and marks the seat
`parked` in its bridge state. A notification card + TTS alert is raised to the user
("<persona>'s seat is parked at the rate-limit dialog").

**R2 — Action, human-word-gated.** A `resume <persona>'s seat` action, triggerable ONLY by
(a) the user's live voice word through the listener, or (b) a tap on the notification card.
The LISTENER injects the un-park keystroke into the pane. Sessions/managers can REQUEST a
resume (which raises the card/alert) but can never trigger the injection themselves —
request ≠ authority, consistent with non-launderable authorization.

**R3 — Audit.** Every resume event is logged: timestamp, pane/session id, persona, trigger
channel (voice | card-tap), requesting session if any. Log surface: listener log + a
`system-events` commons post so fleet managers see recoveries.

**R4 — Consent unambiguity.** The trigger channels in R2 are physically incapable of being a
timeout default (live voice utterance; physical tap). This is the property the classifier could
not establish for the manager-relay path, and the reason the capability moves to the listener.

**R5 — Scope minimality.** The primitive sends ONLY the dialog-dismissal keystroke sequence for
recognized dialog states (rate-limit dialog v1; extensible registry for other park states).
It is NOT a general send-keys channel.

## 4. Interim protocol (in force until built)

1. Manager detects the parked seat, diagnoses, composes the exact one-liner
   (e.g. `tmux send-keys -t <pane> Enter`).
2. Manager hands it to Rick (notify + abstract); Rick fires it himself with the `!`-prefix
   (runs as a raw shell command in his session — no model turn, no classifier judgment).
3. If Rick is unavailable and the seat blocks critical-path work: reap-and-takeover per
   manager-autonomy doctrine, **memento-first** (archaeology only when the dialog blocked the
   memento — postgame decision 2 precedence).

## 5. Acceptance sketch

- AC1: listener flags a synthetic rate-limit-dialog pane as `parked` within one poll cycle.
- AC2: voice "resume <persona>'s seat" un-parks; manager `resume request` raises the card but
  injects nothing.
- AC3: every resume produces the R3 log entry + commons post.
- AC4: non-recognized pane states are never injected into (R5 negative test).
