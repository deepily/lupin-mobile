## Context

The cosa-voice MCP server (v0.3.0) extended the `ask_yes_no` tool contract to a **tri-state** return value: `"yes"`, `"no"`, or `"neither"` (each optionally suffixed with `[comment: ...]`). `"neither"` is the explicit "this question needs re-framing" escape hatch — never a default, always requires a deliberate user click.

The parent-Lupin web client already implements the tri-state UI (`⊘ Neither` button at `src/fastapi_app/static/js/notifications.js:13792-13794`) and the backend endpoint `POST /api/notify/response` accepts the literal verbatim (`Dict[str, Any]` request body; no enum constraint; prediction engine normalizes generically). **Lupin Mobile is the only surface still on the 2-button binary.**

This plan brings mobile to parity with the MCP contract + web UI in a single focused session.

### Why now
Recorded as **PRIORITY 1 next-session work** by user on 2026-05-11 (planning-only session `fe7679c9`, commit `29e8d6d`). User just confirmed (this session) that the mobile gap exists and asked for a plan.

### Intended outcome
- Mobile prompt sheet renders a third "Neither" button alongside Yes/No.
- Tapping Neither emits `responseValue: "neither"` (or `"neither [comment: ...]"` when comment field is populated) via the existing `NotificationsRespond` event — unchanged plumbing downstream.
- Widget + integration tests cover all three branches.
- Test baseline moves 298 ✅ → 301 ✅ (+3 net new tests).
- No backend changes, no cross-repo coordination needed.

### Phase 2 — Extend `_YesNoBody` widget

**File**: `lib/features/notifications/presentation/interactive_prompt_sheet.dart`

**Edit target**: `_YesNoBody.build()` Row at lines 134-152.

**Change**: Replace the 2-button Row (No | Yes) with a 3-button Row (No | Neither | Yes). Keep `Expanded` flex behavior so all three buttons share width equally; reduce gap from 12 → 8 pixels to fit three buttons cleanly.

**Visual hierarchy** (matches Material 3 conventions + parity with web UI's de-emphasized `⊘ Neither` styling):
- **No** — `OutlinedButton` (secondary, unchanged)
- **Neither** — `TextButton` wrapped in `Tooltip(message: "Neither — the question itself needs re-framing")`. Label: `"⊘ Neither"` (mirrors web's `⊘` glyph and label).
- **Yes** — `FilledButton` (primary, unchanged)

**Emit semantics**: same `_withComment("neither")` wrap as Yes/No paths. The trailing `[comment: ...]` suffix already works because `_withComment` is value-agnostic.

**Rationale for hierarchy**:
1. cosa-voice contract says "Neither is never a default" → use the most de-emphasized Material button (`TextButton`).
2. Yes stays primary (right-most + filled) to preserve the existing user muscle memory.
3. No stays secondary-emphasis (left-most + outlined).
4. Neither lives in the middle as a deliberate-but-de-emphasized escape hatch.

5. **Gap width** → 8px (down from 12px) to fit three buttons cleanly on small screens.
6. **Comment field behavior** → unchanged (no auto-focus, no required-on-neither nudge). Future enhancement.
