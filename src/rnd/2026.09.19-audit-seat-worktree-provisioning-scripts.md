## Q2 — link direction, and does anything write into the shared tree?

**Direction is correct in both link scripts.** `ln -s "$SOURCE" "$LINK"` where `$LINK` is always inside `$TARGET` (the worktree) and `$SOURCE` is in `$MAIN_REPO`. The link lives in the disposable tree and points at the durable one — never the reverse. Both refuse outright when target == main (exit 3), so main can never be linked to itself.

**Nothing writes files into the shared tree.** The only writes `provision-seat-worktree.sh` makes into main's directory are `mkdir -p "$MAIN/.claude/worktrees"` and `git worktree add` — the sanctioned lane, confirmed gitignored here by `git check-ignore -v`: `.gitignore:2:.claude/*`. The `worktree lock` call writes to `.git/worktrees/<name>/locked`, metadata rather than working tree.

**The shared-mutable-state question is handled explicitly, and better than I expected.** This is the exact hazard the fleet's "a copy does not merge" rule covers, wearing a symlink, and the deny reasoning names it:

- **`.dart_tool/` is denied** even though it is untracked and 126 MB and looks exactly like a borrowable artifact. The header's reason: `flutter pub get` and `flutter test` both *rewrite* `package_config.json` inside it, so through a symlink those writes land in the main checkout's `.dart_tool/` and two seats testing at once corrupt each other's package resolution and main's with it. Remedy is regeneration — `flutter test` runs `pub get` itself when `package_config.json` is missing, so the tree self-heals.
- **`build/` is denied** — a symlinked output directory means a build in a throwaway tree writes into the shared checkout.
- **`pubspec.lock` is copied, not linked**, precisely so a seat's `pub get` cannot silently re-pin the shared checkout's dependency versions. Both wrong answers (link it / leave it) are stated with their failure modes.
- **Secrets are denied by name** — `android/app/google-services.json`, `CLAUDE.local.md`, anything key-shaped, with the reasoning that a key-dependent test *skipping* is the remedy for that family.

**One accepted shared write, and I agree with accepting it**: the SDK writes into its own tree (`flutter/bin/cache/`, version stamps). Two seats running `flutter test` share one cache. The header names it rather than hiding it, and the argument is right — that is *already* true with a single checkout and a single SDK, so linking preserves current behaviour rather than introducing a hazard. The alternative is 18 GB of duplicated toolchain across eight seats plus a drift surface the moment anyone runs `flutter upgrade`.

## Q3 — destructive verbs

**None, in any of the three.**

| Verb | Occurrences |
|---|---|
| `rm -rf` | 0 |
| `git checkout` / forced checkout | 0 |
| `git stash` | 0 |
| `git add -A` / `git add .` | 0 |
| `git reset` / `git clean` | 0 |
| `git worktree remove` | 0 |

- The only `rm` in each script is **single-argument**, on a path guarded by `[[ -L "$LINK" && ! -e "$LINK" ]]` — a dangling symlink it created itself. Anything else that exists at the target produces a REFUSAL, not a deletion: *"It is not mine to delete — inspect it and remove it yourself if it is stale."*
- `set -euo pipefail` in all three.
- `provision` never removes a worktree; removal belongs to teardown and the janitor, and no remove verb is present.
- **Path traversal is blocked.** The seat name is sanitized with `tr -c 'A-Za-z0-9._-' '-'` and then prefixed with a literal `seat-`, so a seat named `..` becomes the directory `seat-..` rather than escaping the lane.
- Both link scripts avoid a SIGPIPE class the fleet has been bitten by before: reading `git worktree list` into a variable instead of piping into a short-circuiting reader, which on a long worktree list turned `pipefail` + `set -e` into a silent exit 141 that read like success.

## Findings

### F1 · MINOR · the fix is not installed, so the defect it closes is live right now

The three scripts exist in lupin-mobile only on `seat-sam-worktree-scripts` (`0a30d8c`). On the current branch head (`3f807f0`) `src/scripts/` contains none of them.

Until it merges, `spawn_sessions( project="lupin-mobile" )` finds no scripts, reports `worktree_status: "script_absent"`, and **degrades to placing the seat in the main checkout rather than refusing** — so the failure is silent unless someone reads `worktree_status`. That is row `133f34ea`'s exact shape, and per the port's own header it has already happened twice in this repo: 2026-09-14 (two builders moved by hand) and 2026-09-19 (two review seats in the live tree while the manager held uncommitted changes there and committed from it).

**This is an argument for merging sooner, not a caveat against merging.**

### F2 · MINOR · the `pubspec.lock` copy never refreshes

The copy loop:

```bash
if [[ -e "$DST" ]]; then
    echo "ALREADY=$rel"
    continue
fi
```

An existing `pubspec.lock` is left alone forever. A seat tree that outlives a dependency bump in main keeps the old pins, and the script's own stated failure mode applies in the other direction — *"a suite that passes there and fails here, or worse passes both while testing different code, is a false green with no visible cause."*

The script gets link-versus-copy exactly right and then has no staleness story for the copy half. Cheapest honest fix is a line in the header naming it; a real fix would compare against main's and re-copy when they differ, which costs one `cmp`.

## Chased and came back clean

Named so that a silent area is not mistaken for an unreviewed one.

**1. The detached-HEAD work-loss seam — I expected to find this and it is closed.**
`provision-seat-worktree.sh` creates trees with `git worktree add --detach`, so a seat has **no branch**. Every protection in `worktree_reaper.py` is branch-shaped: it commits uncommitted edits *to the branch* (`:484`) and relies on `git branch -d` refusing unmerged work (`:609`). A detached worktree's HEAD reflog lives in `.git/worktrees/<name>/` and dies with the directory, so commits made by a reaped seat should have been unreachable and collectable.

They are not. `:467` computes `detached = ( branch == "HEAD" )`, and `:470-478` **mints a rescue branch before removal** so the WIP commit and the current HEAD stay reachable, with `rescue_branch` in the documented return shape. Anticipated, not lucky.

**2. The `flutter/` → `/flutter` gitignore change.**
`flutter/` (trailing slash) matches a *directory at any depth*; `/flutter` matches a file, symlink or directory *at the root only*. Two things to check, both check out:
- The fix is real — a symlink named `flutter` is not a directory, so under the old pattern it showed as `?? flutter` in every provisioned worktree: untracked, not ignored, one `git add -A` from committing a machine-specific absolute path. In the live seat tree `git status` is clean but for an unrelated `android/local.properties`.
- No coverage was lost by the narrowing. The only nested `flutter` directory is `.dart_tool/build/generated/flutter`, independently ignored at `.gitignore:68` (`.dart_tool/`). Verified with `git check-ignore -v`.

**3. "The name is a contract" — the justification for a Flutter repo shipping `link-worktree-venv.sh`.**
True and load-bearing. `cosa/utils/worktree_venv.py:46` hard-codes `os.path.join( "src", "scripts", "link-worktree-venv.sh" )` and the spawn path calls exactly that. A correctly-named `link-worktree-flutter.sh` would be better English and would **never be invoked** — the spawner would keep reporting `script_absent`. The odd name is the right call.

**4. All three are wired into the spawn path, not merely present.**
`seat_worktree.py:59` → provision · `worktree_venv.py:46` → SDK · `worktree_artifacts.py:43` → artifacts, with both provisioners imported at `agents/shared/worktree_context.py:37-38`. I initially suspected the artifacts script was orphaned because it is absent from `worktree_venv.py`; a repo-wide grep disproved that before it reached the report.
