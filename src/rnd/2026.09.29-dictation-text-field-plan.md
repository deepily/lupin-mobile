# DictationTextField: the append-mic as the default on every text box

Rick, 2026-09-28: the append mic "should be default behavior everywhere within the mobile app." This plan covers the census, the shared widget, the two bloc-owned exceptions, and the migration order.

## 0. Verdict

- **38 text inputs in `lib/`: 13 get a mic (mic-yes), 18 do not (mic-no), 7 are special (6 sites, one of them two lines).**
- **One widget, `DictationTextField`, owns its session and its dispose-cancel.** It replaces four hand-written copies of the state machine and removes the "correct only by tree order" bug in `focus_chat_pane.dart`.
- **Two surfaces keep their bloc-owned session: Quick Ask and Broadcast.** Recommendation: document them as the exception, do not add an escape hatch (§3).

## 2. The shared widget

Shape settled on row cc4e73ed (Chloé's proposal, accepted by Maya): **it takes the service, builds its own session, and never accepts one.** Then no ancestor can hand in a session with a foreign lifetime.

```dart
DictationTextField( {
  Key?                    key,
  required TextEditingController controller,
  AsrService?             asr,                  // null (and no scope) => no mic, plain TextField
  MicPermissionRequester? requestMicPermission, // test seam, defaults to permission_handler
  InputDecoration         decoration,           // the widget adds the mic as suffixIcon, never replaces one
  int?  maxLines, int? minLines, bool enabled, TextInputType? keyboardType,
  ValueChanged<String>? onChanged, ValueChanged<String>? onSubmitted,
  FocusNode? focusNode, bool autofocus,
  Key?  micKey,                                 // TestKeys hook; existing sites keep their keys
} )
```

Behavior it owns (each rule already exists in the tree; this collects them):

- **Session:** one `VoiceCaptureSession( asr:, requestPermission: )`, created once in `initState`.
- **Dispose:** cancels when the recorder is running **or** transcribing, and invalidates any transcription in flight. This is `VoiceReplyField`'s rule (the correct one). It replaces `OpenEndedPromptBody.dispose` (guarded on `listening` only) and `_FocusChatPaneState.dispose` (never cancels).
- **Splice:** `spliceDictation` unchanged (`lib/services/asr/dictation_splice.dart`). The caret is remembered at start; a mid-recording edit voids it and the words go to the END; a blank transcript changes nothing, selection included.
- **States:** idle / listening / transcribing, and the mic is disabled while transcribing. A stale result still frees the mic (María's finding on 30efd26).
- **Errors:** the session's own strings (`permissionDeniedMessage`, `nothingHeardMessage`), shown as the decoration's `errorText`, not a new widget.
- **Disabled box:** `enabled: false` disables the mic (the won't-fix box while busy).
- **Suffix collision:** if the caller's decoration already has a `suffixIcon`, the mic goes before it in a `Row`. No current mic-yes site sets one.

**Getting the service without every site calling `ServiceLocator`:** add a small `DictationScope` `InheritedWidget` at the app root that exposes the `AsrService` and a one-recorder guard (below). `DictationTextField` uses `asr ?? DictationScope.maybeOf( context )`. With neither, it renders a plain `TextField`, so every migration stays additive and every existing widget test that builds a bare `MaterialApp` still passes. **Decision for Rick/Tiffany:** this softens "asr null ⇒ no mic" to "asr null and no scope ⇒ no mic". Without the scope, 13 sites each read `ServiceLocator`, which is exactly the pattern `focus_chat_pane.dart:113` uses and is harder to fake in tests. Recommendation: add the scope.

**One recorder at a time:** `AsrService` is a shared singleton. The scope holds an `activeOwner` notifier; a second mic press while another box records is **disabled**, the same rule `new_ticket_sheet.dart:_toggleMic` uses (`_mic == listening && _micField != field` returns). It never auto-stops the other box, because that would silently truncate a sentence. Outside a scope, the guard falls back to `asr.isCapturing`.

## 3. Quick Ask and Broadcast: separate, documented exceptions

**Quick Ask.** `QuickAskBloc` builds its own `VoiceCaptureSession` (`quick_ask_bloc.dart:164`) and reads `session.epoch` to key its spoken-stream bookkeeping (`_opEpoch`, `:169`, used at `:206`, `:213`). A widget that built its own session would put **two sessions on one screen over one `AsrService`**. Its record control is a hold-to-talk button driving bloc events, not a text box, so there is nothing for the decorator to wrap.

Options:

| option | for | against |
|---|---|---|
| **A. Quick Ask keeps its bloc path, documented as the exception (recommended)** | no lifetime hole; the epoch stays where the bookkeeping lives | one surface stays outside the rule |
| B. Widget accepts a caller-owned session | uniform look | re-opens exactly the hole the shape closes: an ancestor hands in a session that outlives, or is cancelled under, the child |
| C. Move the bloc onto the scope's guard | one recorder rule everywhere | touches a tested, working bloc for no user-visible gain |

**Recommendation: A, plus a cheap half of C:** the bloc registers as `activeOwner` in the scope while its phase is `recording`, so a `DictationTextField` on the same screen (the interview-answer box, once given a mic) is disabled during a Quick Ask recording, and the reverse. Until that lands, the Quick Ask interview box stays mic-less (`OpenEndedPromptBody` with no `asr`), exactly as today.

**Broadcast** (`broadcast_pane.dart:183`, `broadcast_bloc.dart:236`) is the same situation: a bloc-owned `VoiceCaptureSession` behind `BroadcastMicToggled`, and the text is mirrored into bloc state by `BroadcastBodyChanged`. Same recommendation: leave it, list it as the second exception. **Not verified:** whether the Broadcast bloc uses `spliceDictation` or replaces the body. I did not read that handler. Check before deciding whether it deserves its own row.

## 5. Test plan

**Widget tests** (`test/unit/dictation/`, a fake `AsrService` and an injected `requestMicPermission`):

| test | protects |
|---|---|
| permission refused → error text, no recording | the seam that lets denial be tested at all |
| dispose while listening → recorder cancelled | the row a1c12c6e bug (silenced TTS) |
| dispose while transcribing → result dropped, nothing lands | the case the `listening`-only guard missed |
| **caret in the middle**: set `controller.value` directly, dictate, words land at the caret | `tester.enterText` always leaves the caret at the END, so this case cannot be written with it |
| edit during recording → words go to the END | Chloé's M1 |
| blank transcript → value unchanged, selection included | the splice rule |
| two boxes, one recorder → second mic is disabled | the shared `AsrService` |
| stale result still frees the mic | María's finding on 30efd26 |
| `asr` null and no scope → no mic button rendered | additive migration |
| `enabled: false` → mic disabled | the won't-fix box |

**Census guard** (`test/unit/dictation/census_test.dart`): scans `lib/` for `TextField(` and `TextFormField(` and compares the per-file counts to a checked-in allowlist with each entry marked yes / no / special. A new text box fails the test until someone classifies it. This is what makes "default everywhere" stick after this plan is done.

**Per-migration**: the site's existing widget tests must pass unchanged (the `TestKeys` are preserved through `micKey`), plus one new test per site: tap the mic, fake transcript, the controller holds it.

**Negative controls, run and reverted, one per step:**

1. Step 0: remove the dispose-cancel → both dispose tests go red.
2. Step 1: re-add the `listening`-only guard → the "dispose while transcribing" test goes red.
3. Step 2: make the splice follow the live caret after an edit → the M1 test goes red.
4. Step 6: drop the one-recorder guard → the two-box test goes red.

**Not automatable, stated plainly:** real microphone capture, the OS permission dialog and audio-focus behavior on the device. Those stay device checks (Rick's rule: phone checks only for real-device concerns). The widget-level behavior above is fully covered by fakes.

## 6. Risks

- **Shared recorder.** One `AsrService` for the whole app; §2's guard is the mitigation and step 6 is where it is proven.
- **Silent abandonment.** An uncancelled capture strands the TTS hold for the rest of the app session, with no indicator (row a1c12c6e). The dispose rule is the single most important behavior in the widget.
- **`enterText` trap.** Any new dictation test must set `controller.value` for caret cases.
- **Layout.** Multi-line boxes (`maxLines` 4 to 10) need the mic pinned top-right, not vertically centered on the whole box. Check on the agentic forms in step 5.
- **Dictating into the wrong kind of field.** The census makes the mic-no list an explicit decision; S1 and S2 are the two open ones.
