## 3. The one finding that shapes the plan

Three rules account for 1,189 of the 1,834 findings: `bare-ref`, `iso-date` and `dated-banner`. They exist to keep history out of pages that say what the code does now.

Most of mobile's live pages are not that kind of page. `history.md`, the decisions log in `TODO.md`, the decisions record and the post-games are records. A date and a ticket id are what a record is for. Removing them to reach zero would destroy the page.

So the 1,834 findings are not 1,834 defects. I count 645 language findings, and 1,189 dates and ids that sit where they belong.

## 4. Proposal: three kinds of page

Each live page is put in one class, by name, in one data file. A page with no class is treated as a reference page, so a new page gets the strict rules by default.

### 4.1 Reference pages

They say what is true now. All nine rules apply, on every line.

| File | Findings to fix |
|---|---|
| `CLAUDE.md`, `README.md` | 0, already clean |
| `src/docs/docstring-standard.md` | 23 |
| `test/fixtures/commons/README-broadcast.md` | 58 |
| `test/fixtures/README.md` | 4 |
| `tool/doc_lint/VENDORED.md` | 2 |
| `test/service_integration/README.md` | 1 |

Total to fix: 88. When a file reaches zero, the hook refuses any finding anywhere in it.

### 4.2 Living records

They are added to over time, and their dates and ids are the content. The three history rules do not apply. The six language rules do.

| File | Language findings | Proposal |
|---|---|---|
| `src/docs/decisions/README.md` | 81 | clean to zero, then block the whole file |
| `bug-fix-queue.md` | 6 | clean to zero, then block the whole file |
| `src/docs/post-games/README.md` | 0 | block the whole file at once |
| `history.md` | 253 | block new and changed lines only; do not rewrite old entries |
| `TODO.md` | 143 | block new and changed lines only; do not rewrite old entries |

Why `history.md` and `TODO.md` are not rewritten: their old entries move to `history/` and `todo-archive/` at each archive pass, and those folders are ruled out of the cleanup. Rewriting entries that are about to become archive is the same waste.

### 4.3 Finished records

A post-game or a phone check is written once and not edited again. The four post-games and the one phone check hold 304 findings. I propose they are left as they are, for the same reason as the archives. A new one is checked as a living record when it is first committed, so every line of it must pass the six language rules.

### 4.4 What this adds up to

After the work, every commit that adds or changes a markdown line is checked, and a finding refuses the commit. Nothing new can get in.

## 5. Steps

Each step ends with a check a machine runs.

1. **Page classes.** Add `tool/data/markdown_scope.txt`: each path or folder with its class (reference, living record, finished record, archive, vendored wrapper). `tool/lint_markdown.py` reads it and drops the three history rules for records. The vendored linter under `tool/doc_lint/` is not edited. Check: a test fails when a tracked markdown file matches no class, and when a record is given a history-rule finding.
2. **Clean the reference pages.** Fix the 88 findings. Check: `lint_markdown.py --strict` on those files exits 0.
3. **Clean the two records.** Fix the 87 findings in the decisions record and the bug-fix queue. Check: the same command on those files exits 0.
4. **Make the hook block.** Replace the warn step in `tool/pre_commit_gate.py` with a blocking one. A finding on a staged line refuses the commit. A file listed as held at zero is refused for a finding on any line. Check: tests for a refused bad line, a refused finding on an untouched line of a held file, an allowed commit over old lines of `history.md`, and an allowed commit under `history/`.
5. **Merge gate.** Add the same check to `tool/merge_gate.py`, so a commit made with `--no-verify` is caught at merge. Check: a tool test with a seeded finding.
6. **Demonstration.** In a fresh clone and a fresh worktree, never pushed and removed afterwards: a seeded bad markdown line is refused, a clean one is allowed, and the exit codes are recorded on the row.
7. **Wrappers.** When María's row `8b32de78` lands and the wrappers are reinstalled at zero, move `.claude/commands` to held at zero. Until then the folder stays warn only, so a reinstall is not refused by the old findings it carries.
8. **Review and close.** A reviewer that did not write the change reads the whole range. The merge gate runs. No push without Rick's word.

Steps 1 to 6 are one sitting of work. Step 7 waits on María.
