# WS Lifecycle: Wire `WebSocketService.connect()` to `AuthAuthenticated`

## Context

The 2026-04-19 post-login investigation surfaced a concrete runtime bug: `WebSocketService.connect()` is never invoked after a successful login. As a result, the WS message stream (`_messageController.stream` in `lib/services/websocket/websocket_service.dart:33`) is a live broadcast stream that never receives any messages, because no underlying `WebSocketChannel` is ever opened. The `_dispatchWsEvent` router in `lib/app.dart:53-80` — which maps `notification_queue_update`, `queue_*_update`, and `claude_code_*` events to their respective BLoCs — is **dead code at runtime** today.

User-visible consequences:
- Track-C inbox auto-refresh (wired 2026-04-17) silently never fires.
- Queue dashboard never sees CJ-flow transitions.
- Claude Code interactive chat cannot receive assistant messages.
- Only REST-backed actions (login, inbox fetch, respond, dispatch, etc.) actually work end-to-end.

The fix is small and surgical: connect on `AuthAuthenticated`, disconnect on `AuthUnauthenticated` / `AuthError`.

---

## Approach — BlocListener in `app.dart`

Wrap the existing `MultiBlocProvider` child in a `BlocListener<AuthBloc, AuthState>` that reacts to auth-state type transitions and drives the singleton `WebSocketService` from DI.

### Why this placement

| Alternative | Rejected because |
|-------------|------------------|
| Side-effect inside `AuthBloc._onLogin` / `_onBiometric` | Domain BLoC shouldn't import transport services; WS is infrastructure. Also: three separate call sites to keep in sync (login, biometric, validate). |
| Listener in `AuthGate` | AuthGate rebuilds on every auth-state change; wiring WS lifecycle at that layer couples it to UI tree state. Also, `AuthGate` only mounts `authenticatedChild` for `AuthAuthenticated`; handling `AuthUnauthenticated` cleanly is awkward. |
| Separate `WsLifecycleBinding` widget above `MultiBlocProvider` | Viable but adds a layer for no gain. A `BlocListener` sibling inside the existing tree is simpler. |

`BlocListener` at the `MultiBlocProvider` child layer runs once per auth-state transition, regardless of UI tree, and gives symmetric connect/disconnect semantics tied to a single source of truth.

### Connect/disconnect matrix

| From state | To state | Action |
|-----------|----------|--------|
| anything | `AuthAuthenticated` | `await ws.connect( userId: state.userId )` (guard: `if ( !ws.isConnected )`) |
| anything | `AuthUnauthenticated` | `await ws.disconnect()` (guard: `if ( ws.isConnected )`) |
| anything | `AuthError` | `await ws.disconnect()` (token invalid or startup failure — tear down) |
| `AuthAuthenticated` | `AuthAuthenticated` (e.g., token refresh) | **no-op** (filter via `listenWhen` on `prev.runtimeType != curr.runtimeType`) |
| `AuthInitial` / `AuthLoading` | `AuthBiometricRequired` | no-op (no access token yet) |

`listenWhen` on runtime-type transition prevents duplicate `connect()` calls on successive `AuthAuthenticated` emissions (e.g., biometric unlock then `AuthSessionValidationRequested`).

### Concrete edit (`lib/app.dart`)

Add import:
```dart
import 'features/auth/domain/auth_state.dart';
import 'services/websocket/websocket_service.dart';
// (flutter_bloc already imported)
```

Wrap the existing `MultiBlocProvider`'s child tree:
```dart
// Inside build(), replace the current `MaterialApp(...)` direct return with:
child: BlocListener<AuthBloc, AuthState>(
  listenWhen: ( prev, curr ) => prev.runtimeType != curr.runtimeType,
  listener : ( ctx, state ) async {
    final ws = ServiceLocator.get<WebSocketService>();
    if ( state is AuthAuthenticated ) {
      if ( !ws.isConnected ) {
        await ws.connect( userId: state.userId );
      }
    } else if ( state is AuthUnauthenticated || state is AuthError ) {
      if ( ws.isConnected ) {
        await ws.disconnect();
      }
    }
  },
  child: MaterialApp( /* existing */ ),
),
```

No changes to `AuthBloc`, `AuthGate`, `WebSocketService`, or DI.

## Testing

### Strategy

Unit-test the listener logic in isolation rather than via an app-level widget test. Widget-testing the whole `LupinMobileApp` tree pulls in the full DI graph, which is heavyweight and brittle.

Two options, preferred first:

**Option A — Extract lifecycle wiring to a small testable widget** (Recommended)

New: `lib/features/auth/presentation/ws_lifecycle_listener.dart`
```dart
class WsLifecycleListener extends StatelessWidget {
  final Widget child;
  final Future<void> Function( String userId ) onAuthenticated;
  final Future<void> Function() onSignedOut;

  const WsLifecycleListener( {
    super.key,
    required this.child,
    required this.onAuthenticated,
    required this.onSignedOut,
  } );

  @override
  Widget build( BuildContext context ) {
    return BlocListener<AuthBloc, AuthState>(
      listenWhen: ( prev, curr ) => prev.runtimeType != curr.runtimeType,
      listener : ( _, state ) async {
        if ( state is AuthAuthenticated ) {
          await onAuthenticated( state.userId );
        } else if ( state is AuthUnauthenticated || state is AuthError ) {
          await onSignedOut();
        }
      },
      child: child,
    );
  }
}
```

Usage in `app.dart`:
```dart
WsLifecycleListener(
  onAuthenticated: ( userId ) async {
    final ws = ServiceLocator.get<WebSocketService>();
    if ( !ws.isConnected ) await ws.connect( userId: userId );
  },
  onSignedOut: () async {
    final ws = ServiceLocator.get<WebSocketService>();
    if ( ws.isConnected ) await ws.disconnect();
  },
  child: MaterialApp( /* existing */ ),
)
```

Test: `test/widget/auth/ws_lifecycle_listener_test.dart`
- Build the widget with a `MockAuthBloc` (mocktail) and two mock async callbacks.
- Emit state sequences and assert callback invocations:
  1. `AuthLoading` → `AuthAuthenticated(userId:'u-1',...)` → `onAuthenticated('u-1')` called once.
  2. `AuthAuthenticated` → `AuthAuthenticated` (same type) → neither callback called (listenWhen filter).
  3. `AuthAuthenticated` → `AuthUnauthenticated` → `onSignedOut` called once.
  4. `AuthInitial` → `AuthError` → `onSignedOut` called once.
  5. `AuthInitial` → `AuthBiometricRequired` → neither callback called.

**Option B — Direct widget test against `app.dart` with a registered mock WebSocketService**

Requires a test harness that resets `ServiceLocator` and re-registers `WebSocketService` as a `MockWebSocketService`. Higher setup cost; brittle if DI graph changes. Skip unless Option A is deemed over-engineered.

## Edge cases

- **Token refresh emits a new `AuthAuthenticated` with a new accessToken**: `listenWhen` filters identical runtime types → no reconnect. **Known limitation**: WS authenticates once at connect time via `readAccessToken()`; a refreshed token won't reach the WS session. Acceptable for this session — file a separate follow-up TODO if WS-level token rotation matters.
- **`AuthServerContextChanged`**: forces `AuthUnauthenticated` → disconnect fires naturally. No additional handling needed.
- **Reconnect race**: `WebSocketService.connect()` has `if ( _isConnected ) return;` early-return. Two rapid `AuthAuthenticated` emissions are safe. A connect-in-flight race is theoretically possible (`_isConnected` flips `true` only after `ready`); acceptable for now.
- **Logout mid-reconnect**: `disconnect()` sets `_shouldReconnect = false` and cancels timers. Safe.
- **Biometric path**: `AuthInitial` → `AuthBiometricRequired` → (unlock) → `AuthAuthenticated` fires `connect`. `AuthBiometricRequired` itself does not touch WS. Correct.
