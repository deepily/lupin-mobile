## 6. User-Flagged Priorities — Mobile UX Considerations

### 6.1 Conversation mode — "may lend itself to its own widget set outside the existing UI"

User's instinct is right. On a mobile device, conversation mode is a **whole-app modality**, not a per-card toggle:
- The user is at a distance, screen off, listening via TTS
- Per-session toggle UI on a tiny screen is wasted real-estate
- A dedicated conversation-mode screen with: large mic icon, current session indicator, persona badge, exit button, current notification subtitle — would map better to the at-a-distance use case
- Could be reachable via a global FAB or a single home-screen toggle that dims everything else

This is one of the tasks queued for design (Task #2: "Decide conversation-mode UX placement on mobile").

### 6.2 Focus mode — implicit on mobile?

On the web, focus mode hides 5 vertically-stacked cards down to 1. **Mobile inbox is already single-screen-at-a-time** by virtue of the form factor. The relevant question is whether the mobile inbox should:

- (a) Implicitly focus on one session at a time, with a session switcher (segmented control / drawer / FAB)
- (b) Mirror the web stack with cards and add the same focus pill
- (c) Treat each session as a separate "conversation" the way Telegram/Signal show DMs (one tap to enter a session, swipe to go back)

Option (c) feels most native and may be what the inbox already trends toward. Worth confirming by re-reading the existing inbox code before designing.

### 6.3 Voice personas — straightforward port

Persona color/icon is a card decoration; no special UX problem. The work is:
- Wire `voice_persona_assigned` / `voice_persona_released` into NotificationBloc
- Stamp `voicePersona: VoicePersona?` field onto the conversation/session model
- Render badge in `_NotificationItemCard` (or wherever sender headers live)
- Pipe `voiceId` into `StreamingTtsPlayer.speak()` so the per-session voice is honored, not the backend default
