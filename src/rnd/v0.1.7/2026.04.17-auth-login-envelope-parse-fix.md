# Login bug: `AuthRepository` parses flat tokens but backend returns a nested envelope

**Branch**: `wip-v0.1.6-2026.04.16-tracking-lupin-work`
**Project root**: `/mnt/DATA01/include/www.deepily.ai/projects/lupin/src/lupin-mobile/`

---

## Context

User deployed the current branch to emulator, entered valid credentials, tapped Sign In. Backend returns HTTP 200 with valid tokens + user. Logcat confirms:

```
POST http://10.0.2.2:7999/auth/login → 200
{"message":"Login successful","user":{...},"tokens":{"access_token":"...","refresh_token":"...","token_type":"bearer"}}
```

But UI never navigates to the authenticated app shell. Password field clears; user stays on the login screen. No obvious error feedback reaches the user.

### Root cause (code)

`AuthRepository.login` at `lib/services/auth/auth_repository.dart:55-65`:
```dart
final res = await _dio.post<Map<String, dynamic>>( "/auth/login", data: {...} );
return AuthTokens.fromJson( res.data! );   // ← expects FLAT top-level tokens
```

`AuthTokens.fromJson` at `auth_repository.dart:14-20` reads `access_token` / `refresh_token` from the top level. But the Lupin backend's `LoginResponse` Pydantic model at `src/cosa/rest/auth_models.py:198-219` is a nested envelope:
```python
class LoginResponse( BaseModel ):
    message : str
    user    : UserResponse
    tokens  : TokenResponse   # ← tokens live here, not at top level
```

So `res.data["access_token"]` is null. The `as String` cast throws a `TypeError`, which is NOT a `DioException`, so the inner `on DioException catch` block doesn't catch it. The `TypeError` propagates up to `auth_bloc.dart:120` — the bare `catch (e)` — which emits `AuthError` with a `"Login failed: type 'Null' is not a subtype..."` message. A SnackBar fires for a few seconds and disappears; user doesn't notice.

**`RefreshResponse` has the same envelope** (`auth_models.py:222`): `{message, tokens}`. So `AuthRepository.refresh` at `auth_repository.dart:67-80` has the identical bug. The biometric-unlock path (`_onBiometric` at `auth_bloc.dart:79-98`) will silently drop the session into `AuthUnauthenticated`, forcing password re-entry on every startup — a second, currently-unnoticed bug.

**`/auth/me` returns a flat `UserResponse`** (`auth_models.py:124-171`), so the existing `me()` parse is fine.

### Root cause (tests)

`test/unit/auth/auth_repository_test.dart:56-66` stubs the login response with a FLAT shape that matches the buggy parser, not the real backend. Test passes → false positive. This is exactly the class of bug the golden-fixture layer of the 2026 playbook (`src/rnd/v0.1.7/2026.04.16-flutter-ui-testing-best-practices.md`) is meant to catch.

### Duplicate Dio response log

User saw the same 200 Response logged twice. Root: two chained log interceptors on the shared Dio (a `LogInterceptor` plus a custom `InterceptorsWrapper` in `lib/services/network/http_service.dart`). Cosmetic, unrelated to the login bug — out of scope for this fix.

## Fix — minimal + correct

Three files modified, no new files, no new deps.

### F1. `lib/services/auth/auth_repository.dart` — parse the envelope

**`login()`** — change:
```dart
return AuthTokens.fromJson( res.data! );
```
to:
```dart
final tokensJson = res.data![ "tokens" ] as Map<String, dynamic>;
return AuthTokens.fromJson( tokensJson );
```

**`refresh()`** — change the flat-shape path to the same pattern:
```dart
final tokensJson = Map<String, dynamic>.from( res.data![ "tokens" ] as Map );
tokensJson.putIfAbsent( "refresh_token", () => refreshToken );
return AuthTokens.fromJson( tokensJson );
```

The `putIfAbsent` guard stays — some refresh responses may omit refresh_token (rotating access only).

### F2. `lib/features/auth/domain/auth_bloc.dart` — skip the redundant `/auth/me` round-trip after login

The login response ALREADY contains the user object. `_onLogin` at line 107-117 makes a second HTTP call to `/auth/me` that fetches the same info. Since we're already fixing the parser, extend `login()` to return both tokens + user:

Change `AuthRepository.login()` signature to return a small record/class carrying tokens + user. Update `_onLogin` to use the login-response user directly. This saves ~100ms of startup latency and removes an unnecessary failure mode.

Minimum-viable alternative: keep the `/auth/me` call. The extra round-trip is harmless now that login() is fixed.

**Choosing minimum-viable** for this fix — keep `/auth/me`. Smaller diff, less to review, same user-visible behavior.

### F3. `test/unit/auth/auth_repository_test.dart` — match real backend shape

Update the "login parses access + refresh tokens" test to use the real envelope:
```dart
adapter.handlers["POST /auth/login"] = (_) => _jsonBody({
  "message": "Login successful",
  "user": {"id": "uid-1", "email": "a@b.com", "roles": ["user"],
           "email_verified": false, "is_active": true,
           "created_at": "2025-10-07T01:10:26Z"},
  "tokens": {"access_token": "acc-1", "refresh_token": "ref-1", "token_type": "bearer"},
});
```

Update the "refresh reuses old refresh_token if backend omits it" test similarly — wrap the tokens in `{message, tokens: {...}}`.

Add one new test: `"login throws AuthException (not raw TypeError) when response has wrong shape"` — verifies that a flat (legacy-style) response now produces a sensible error rather than swallowed.

### F4. Widget test — confirm AuthAuthenticated navigates

Add a test to `test/widget/auth/login_screen_test.dart`: seed the mock AuthBloc to emit `AuthAuthenticated` after submit, confirm the UI doesn't stay on the login screen. This covers the "login succeeds → UI navigates" contract at the widget layer.

Actually — the login screen's rendering *doesn't* navigate (`AuthGate` does). A more accurate widget test belongs in a new `test/widget/auth/auth_gate_test.dart`: feed `AuthAuthenticated` → assert `authenticatedChild` renders; feed `AuthUnauthenticated` → assert `LoginScreen` renders. This is what was missing before the bug shipped.

## Stage 2 playbook — fixture-backed repository tests

### Why

Today's `LoginResponse`-envelope bug existed because `auth_repository_test.dart` stubs hand-crafted a FLAT response that matched the buggy parser. The stubs drifted from the real backend; both the app and its tests shared the same wrong mental model; the suite stayed "green" all the way through a real-device failure.

Fixture-backed tests close the drift window: tests load captured JSON files from disk. When the backend shape changes, re-running a capture script regenerates the fixtures and any test still assuming the old shape fails — loudly and locally, before an on-device deploy.

This is the "golden-fixture" layer called out in `src/rnd/v0.1.7/2026.04.16-flutter-ui-testing-best-practices.md`, adapted for repository-layer API contract tests (not widget goldens).

### Scope (this iteration)

Auth endpoints only: `/auth/login`, `/auth/refresh`, `/auth/me`, plus a captured 401 error shape. Notifications, decision-proxy, and agentic follow in a later iteration — proving the pattern first.

### Files to add

- `test/fixtures/README.md` — explains the capture/refresh workflow and redaction rules.
- `test/fixtures/auth/login_response.json` — captured `/auth/login` 200 (tokens + user redacted to stable placeholders).
- `test/fixtures/auth/refresh_response.json` — captured `/auth/refresh` 200.
- `test/fixtures/auth/me_response.json` — captured `/auth/me` 200.
- `test/fixtures/auth/login_error_401.json` — captured 401 response (shape-only, message is fine to keep).
- `test/_helpers/fixture_loader.dart` — two helpers:
  - `Map<String, dynamic> loadFixture( String relativePath )` — reads and decodes JSON from `test/fixtures/`
  - `ResponseBody jsonBodyFromFixture( String relativePath, { int status = 200 } )` — wraps a fixture as a Dio `ResponseBody`.
- `src/scripts/capture-auth-fixtures.py` — Python script (not bash+curl, per the project's testing anti-patterns) that:
  1. Reads `LUPIN_TEST_INTERACTIVE_MOCK_JOBS_EMAIL` + `LUPIN_TEST_INTERACTIVE_MOCK_JOBS_PASSWORD` from env
  2. Hits the running Lupin backend (default `http://localhost:7999`, overridable via `LUPIN_API_BASE_URL`)
  3. Captures `/auth/login` (success + one 401 with bad password)
  4. Uses the access token to capture `/auth/me`
  5. Uses the refresh token to capture `/auth/refresh`
  6. Redacts: replaces real JWTs with `"fixture_access_token"` / `"fixture_refresh_token"`; replaces real `id` with `"uid-fixture"`; replaces real `email` with `"fixture@example.com"`; normalizes timestamp fields (`created_at`, `last_login_at`) to `"2025-01-01T00:00:00+00:00"`.
  7. Writes to `test/fixtures/auth/*.json` with stable key ordering + 2-space indent for clean diffs.

### Files to modify

- `test/unit/auth/auth_repository_test.dart` — swap hand-crafted stub Maps for `jsonBodyFromFixture( "auth/login_response.json" )` (and sibling files). The "wrong-shape" test stays hand-crafted (it's deliberately testing a bad shape).
- `test/unit/auth/auth_interceptor_test.dart` — same swap for the `/auth/refresh` stubs.

### Redaction contract

The capture script MUST redact before writing. Non-negotiable rules:

| Field | Real value | Fixture value |
|---|---|---|
| `access_token` | actual JWT | `"fixture_access_token"` |
| `refresh_token` | actual JWT | `"fixture_refresh_token"` |
| `user.id` (UUID) | actual UUID | `"uid-fixture"` |
| `user.email` | actual address | `"fixture@example.com"` |
| `user.created_at` | real timestamp | `"2025-01-01T00:00:00+00:00"` |
| `user.last_login_at` | real timestamp | `"2025-01-01T00:00:00+00:00"` |

Anything not in this table stays as-is.

### Workflow (developer)

```bash

```

```bash
# confirm the repository tests fail (drift detection in action)
```

### Out of scope (flag for later)

- **Fixture coverage for notifications / decision-proxy / agentic endpoints** — expand after auth proves the pattern.
- **CI job that runs `capture-auth-fixtures.py` on a schedule and opens a PR if fixtures changed** — catches silent backend drift automatically.
- **Contract tests running against a Dockerized backend in CI** — stronger than fixtures but heavier to set up.
- **Golden widget tests via Alchemist** — separate concern (visual regression), not API shape.
