## Architectural decisions

### Date-grouped renderer — Option A
Build a separate `_NotificationItemCard` for the by-date view rather than try to unify `NotificationItem` (44 fields, no delivery state) and `ConversationMessage` (20 fields incl. `state`/`deliveredAt`/`respondedAt`/`responseValue`). Trade: by-date view shows priority/timestamp/title/message/abstract/played/responseRequested but NOT a "responded at X with Y" badge. Avoids cross-repo work and zero risk to existing `_MessageCard` tests.

### Audio focus contention
`AudioArtifactPlayer.play()` calls `TtsOrchestrator.stopAll()` first (already exists at `tts_orchestrator.dart:87-92`). Inverse direction (urgent TTS preempts playback) already covered by `_preemptForUrgent`. No orchestrator changes.

### Audio file size
`DeviceFileSource(file.path)`, NOT `BytesSource`. Podcast MP3s are multi-MB; streams from disk via `IoFileService.downloadToCache()` (which the current player already uses).

### Phase 4a/4b split
- **4a (this slate)**: rebuild `AudioArtifactPlayer` around `audioplayers`. Surface stays compatible (`JobDetailScreen._viewArtifact()` still passes `job.reportPath ?? ''`). Empty path = graceful no-op.
- **4b (deferred)**: after parent Lupin lands `audio_path` mapping → add `audioPath` field to mobile `JobSummary`, switch `JobDetailScreen` to use it. ~10 lines + 1 fixture.

### Audio player testability
Extract a `_PlaybackController` wrapper around `AudioPlayer` so widget tests can mock it (audioplayers requires platform channels and won't run in widget test runner).
