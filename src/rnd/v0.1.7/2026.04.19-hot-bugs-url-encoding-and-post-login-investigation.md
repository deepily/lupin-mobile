## Bug 1 — `NotificationRepository` URL-encoding

### Root cause

`Dio`'s path argument is a string; it does NOT auto-encode. All 14 path-interpolation sites in `lib/features/notifications/data/notification_repository.dart` embed user-controlled strings (senderId, userEmail, userId, project, dateString) directly. Any `/` in those values produces a malformed URL that FastAPI parses as additional path segments — e.g. `/api/notifications/conversation/peer-queue-watch/abc-def/user@x.y` is read as `sender=peer-queue-watch`, `user=abc-def` (wrong).

### Scope

Fix **all** path interpolations with user-controlled inputs, not just `conversation()` / `conversationByDate()`. The bug is systemic; whack-a-mole scope invites regressions. Call sites affected:

| Method | Line | Path params to encode |
|--------|------|------------------------|
| `list` | 59 | `userId` |
| `next` | 77 | `userId` |
| `bulkDelete` | 123 | `userEmail` |
| `senders` | 144 | `userEmail` |
| `sendersVisible` | 167 | `userEmail` |
| `conversation` | 194 | `senderId`, `userEmail` |
| `deleteConversation` | 218 | `senderId`, `userEmail` |
| `conversationByDate` | 238 | `senderId`, `userEmail` |
| `deleteDate` | 271 | `senderId`, `userEmail`, `dateString` |
| `senderDates` | 289 | `senderId`, `userEmail` |
| `activeConversation` | 307 | `userEmail` |
| `projectSessions` | 324 | `project`, `userEmail` |

`notificationId` (played, deleteOne) is UUID-shaped (server-generated, hex+hyphen) — safe, skip.

### Approach

Add a private top-level helper and apply uniformly at path-interpolation sites:

```dart
String _enc( String s ) => Uri.encodeComponent( s );
```

Then `'$senderId'` becomes `'${_enc( senderId )}'` at every affected site. No public API change; call sites need no changes.

### Verification

- Existing tests use slash-free IDs (`s-1`, `u@x.y`) so encoding is a no-op and tests stay green.
- Add one new test in `test/unit/notifications/notification_repository_test.dart` that:
  - Handler key: `"GET /api/notifications/conversation/peer-queue-watch%2Fabc-def/u@x.y"` (encoded form).
  - Call: `repo.conversation( "peer-queue-watch/abc-def", "u@x.y", hours: 24 )`.
  - Asserts the handler matched (fixture-body return).

### Downstream follow-up

- **Fixture-capture slash filter** (`src/scripts/capture-notifications-fixtures.py:111`) — left in place. Its rationale ("FastAPI path-param routing can't match them") is a **server-side** question about whether starlette unescapes `%2F` before segment-splitting. The Flutter-side fix is defensive and correct regardless; the filter's removal depends on verifying server behavior, which is out of this session's scope.
- **Sibling repositories with same bug** — `lib/features/decision_proxy/data/decision_proxy_repository.dart:56,120` has raw `$userEmail` interpolation on `/api/proxy/pending/$userEmail` and `/api/proxy/trust/$userEmail`. Same bug class, tiny fix. Deliberately left out of this session's scope per original TODO; raise as a separate ticket.

## Bug 2 — Post-login behavior investigation

### What we know

- Login flow works (envelope fix landed 2026-04-17, verified on emulator).
- User flagged concern about what happens **after** successful login, without a concrete repro.

### Investigation targets (code read only)

1. **`auth_gate.dart`** — does `AuthGate` redirect cleanly from login screen to home after `AuthAuthenticated`? Any flash of login screen?
2. **`home_screen.dart`** — what fires on first authenticated mount? Does it trigger inbox initial fetch? Any blocking `FutureBuilder` or uninitialized BLoC state?
3. **`app.dart` WS wiring** — when does the WS connect? Is it token-aware (reconnects with new token after login)? What events does it subscribe to initially?
4. **`NotificationBloc` initial state** — does it auto-load the inbox on first subscription, or only on explicit `NotificationsRequested`?
5. **Known side effects** — search for `AuthAuthenticated` listeners across the codebase to map the full post-login fan-out.

### Output

Findings note appended to this doc. If a concrete bug surfaces, convert to a follow-up task; if flow looks clean, close the TODO with a "verified by code read" note and mention emulator spot-check.

### Findings (2026-04-19)

**Concrete bug — WebSocket is never connected after login.**

- `AuthBloc._onLogin` / `_onBiometric` / `_onValidate` all emit `AuthAuthenticated` but do NOT call `WebSocketService.connect()` (`lib/features/auth/domain/auth_bloc.dart:85,113,150`).
- `main.dart` and `AppInitialization.initialize` do not connect WS either.
- `WebSocketService.connect()` is only called from TTS services (`enhanced_tts_service.dart:345`, `tts_service.dart:162`) and the connection manager's own wiring — nothing tied to the auth lifecycle.
- `app.dart._connectWsToBlocs()` subscribes to `ws.stream` at app mount, but the stream is a broadcast `_messageController.stream` with no messages flowing because no one ever calls `connect()`.

**Consequence**:
- Login → Inbox → Respond work end-to-end **because they are REST**, not WS.
- Real-time inbox auto-refresh (`NotificationsExternalUpdate` — the Track-C wiring from 2026-04-17) silently does nothing because no `notification_queue_update` events arrive.
- Same for queue updates, Claude Code interactive messages, etc. The whole WS-event fan-out in `app.dart:54-79` is dead code at runtime.

**Other observations (not bugs, by design)**:
- `NotificationBloc` is lazy — loads inbox only on explicit `NotificationsLoadInbox`. Fires when user taps the Inbox nav card. Correct.
- `LupinHomeScreen` is a static nav-card list — no post-mount fetch. Correct.
- `WebSocketService._authenticate()` sources the Bearer token via `readAccessToken()` at connect time — reads the freshest token. Correct. So if `connect()` is called post-login, auth will use the new token.
- `AuthBloc._onLogout` clears tokens but does NOT call `ws.disconnect()` — if the fix wires `connect()` on login, this should also disconnect on logout.

### Recommended fix (if approved)

Add a `BlocListener<AuthBloc, AuthState>` above (or inside) the `MultiBlocProvider` in `lib/app.dart`:

```dart
BlocListener<AuthBloc, AuthState>(
  listenWhen: ( prev, curr ) => prev.runtimeType != curr.runtimeType,
  listener: ( ctx, state ) async {
    final ws = ServiceLocator.get<WebSocketService>();
    if ( state is AuthAuthenticated ) {
      if ( !ws.isConnected ) {
        await ws.connect( userId: state.userId );
      }
    } else if ( state is AuthUnauthenticated || state is AuthError ) {
      if ( ws.isConnected ) {
        await ws.disconnect();
      }
    }
  },
  child: ...,
)
```

**Why this shape**:
- `listenWhen` on type-change avoids firing on `lastEmail` edits inside `AuthUnauthenticated`.
- Stays out of the auth domain layer (AuthBloc stays token-only).
- Symmetric connect/disconnect tied to auth state — natural lifecycle.

**Test plan**:
- New blocTest-level widget test wiring a `MockAuthBloc` + a `MockWebSocketService` and verifying `connect()` is called on `AuthAuthenticated`, `disconnect()` on `AuthUnauthenticated`.
- Manual emulator spot-check: log in, trigger `ask_yes_no` from server, confirm inbox auto-refreshes.
