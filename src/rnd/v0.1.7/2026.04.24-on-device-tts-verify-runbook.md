## Stub-injection strategy (reference)

The backend `/api/get-speech-elevenlabs` endpoint (at
`src/cosa/rest/routers/speech.py:508`) accepts `debug_simulate_error: true`
in the POST body. When set, the backend skips the actual ElevenLabs call
and emits a `tts_error` WS event with `error_code=quota_exceeded`.

The mobile client exposes this via the `LUPIN_DEV_SIMULATE_TTS_ERROR`
dart-define:

```dart
// lib/services/tts/streaming_tts_player.dart (constructor):
_simulateTtsError = simulateTtsError ?? (
  kDebugMode && const bool.fromEnvironment(
    'LUPIN_DEV_SIMULATE_TTS_ERROR',
    defaultValue: false,
  )
);
```

The flag is `kDebugMode`-gated, so release builds ignore it. Unit tests
verify both true and false paths
(`test/unit/services/tts/streaming_tts_player_test.dart`).

## Gotcha checklist (from TODO.md, pre-verify)

Watch for these on first-run behavior:

- **Channel sound not playing on first install** — Android can delay
  channel-sound activation until the app is relaunched. If the first
  urgent uses the OS default sound instead of `lupin_urgent.mp3`,
  uninstall + reinstall.
- **Audio-focus conflict between notification channel ding and
  audioplayers** — if the ding gets cut short when the voice begins,
  consider either (a) increasing the ding→voice gap, or (b) routing
  both sounds through `audioplayers`.
- **PCM→WAV wrap correctness** — if playback crashes or plays as noise,
  `_wrapPcm24kAsWav` in `streaming_tts_player.dart` is the first place
  to look. 24kHz, 16-bit, mono.
- **Session ID mismatch** — the orchestrator reads
  `WebSocketService.sessionId` at speak-time. If WS isn't yet connected
  (app just opened, no auth yet), the orchestrator correctly falls back
  to `flutter_tts` for that one utterance without entering the 5-minute
  quota window.
