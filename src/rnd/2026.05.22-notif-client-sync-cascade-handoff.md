## Highest-signal output: the wire-contract-grounding cluster-family

### What it was

Krishna 🦚 surfaced the family at Stage 2 across 4 finding-instances:

- **F-Krishna-A1** (Section A) — the 3 event-type case-label strings asserted, only fabricated-tested.
- **F-Krishna-B3** (Section B) — the `speakerphone_changed` payload field names asserted, only fabricated-tested.
- **F-Krishna-D1** (Section D) — AC-D4's senders-fixture not mandated as a live capture.
- **F-Krishna-D2** (Section D) — the WS-path real-wire check rests on the optional AC-D6.

**Single root**: ACs verify a server wire contract against self-authored fixtures / fabricated events — so a fully-green suite does NOT prove the real server contract holds. The feature can silently fail in production with all tests green.

### Severity placement

The Manager classified the family as **inconsistency, NOT foundational → NO user escalation**:

- Each instance is Author-fixable; no user decision required.
- The pattern recurs across sections; it is not a cross-section *conflict* (each section's grounding fix is independent).
- Krishna (the finder) concurred on the classification.

### Shared fix doctrine

> Any AC asserting a server wire contract MUST ground it against the authoritative server-side source — the cosa `valid_types` whitelist + the emit sites — AND/OR a **mandated** (not optional, not "if") live capture with named provenance. Never a hand-authored fixture; never an "if/optional" live-capture.
