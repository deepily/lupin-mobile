# JDK 25 build failure — why upgrading Gradle does not fix it

Date: 2026-09-15 · Author: Tiffany 💍 (research subagent, read-only) · Rows: c51e92da, 9b1f7701

## The question

The laptop build died with a bare `25.0.3` as its entire error. First recommendation was "install
JDK 21 and point Flutter at it". Rick pushed back, correctly: *why not upgrade Gradle to something
that supports JDK 25, rather than install an older Java?* This is the evidence.

## Answer: Gradle is not the blocker — Flutter's own tooling is

The vendored SDK caps what it will accept, in
`flutter/packages/flutter_tools/lib/src/android/gradle_utils.dart`:

```
maxKnownAndSupportedGradleVersion = '8.12'
maxKnownAndSupportedAgpVersion    = '8.7.3'
```

Those are **exactly** the versions this repo pins. We are already at Flutter 3.32's ceiling, so
there is no Gradle 9 to move to without moving Flutter first. Flutter 3.32's own Java table tops out
at Java 24.

And the destination is not supported either: **AGP has never listed JDK 25**. AGP 9.4.0 (Sept 2026,
current) still says JDK 17 minimum and default. `flutter/flutter#187223`, "Java 25 Support in Flutter
Android Builds" (opened 2026-05-28), is still open and reports real breakage on JDK 25 — its own
suggested workaround is to use JDK 17 or 21.

| AGP 9.4.0 (Sept 2026, latest) | Gradle 9.6.0 min · JDK 17 min/default · **no JDK 25 row** | [AGP release notes](https://developer.android.com/build/releases/gradle-plugin) |

| Android Studio bundled JDK | JBR **21** (since Ladybug 2024.2.1) | [Java versions in Android builds](https://developer.android.com/build/jdks) |

## Is JDK 21 "old"?

No — it is the current LTS and what the Android toolchain ships and targets. Android Studio bundles
JBR 21, and Flutter resolves Android Studio's bundled Java first, then `JAVA_HOME`, then PATH.
JDK 25 is the *newer* one, not the *supported* one; nobody builds Android on 25 today.

## The three paths

| Path | Files touched | Time | Risk |
|---|---|---|---|
| **(a) Point the build at JDK 21** | none in the repo — `flutter config --jdk-dir=<jdk21>` writes user-level config | ~15 min | none, reversible |
| **(b) Chase JDK 25** | Flutter 3.32 → 3.47 first, then `settings.gradle.kts`, `gradle-wrapper.properties`, `app/build.gradle.kts`, the built-in-Kotlin migration, ~8 pub deps | days | ends on a JDK that AGP still does not list, with an open Flutter bug |
| **(c) Wait** | none | 0 | fine — nothing is broken except the JDK choice |

**Recommendation: (a).** Path (b) is a Flutter upgrade wearing a Gradle costume, and it still does
not end in a supported JDK 25.

## Second question: how far behind is our Flutter, and is upgrading worth anything?

Vendored: **3.32.0**, stable, framework commit 2025-05-19, Dart 3.8.0. Current stable: **3.47.1**
(2026-08-19), Dart 3.13.1 — five stable releases (3.35, 3.38, 3.41, 3.44, 3.47) and about 15 months.

- **It is the only unlock for Gradle 9**, since `flutter_tools` refuses anything above its cap.
  3.44 introduced AGP 9 support; 3.47 ships AGP 9.1.0 / Gradle 9.3.1 / KGP 2.4.0 templates. But
  3.47's verified set still says Java 17 minimum, and AGP still does not list 25.
- **What it would break here**: the AGP 9 + built-in-Kotlin migration rewrites `android/`. `minSdk`
  is already 24, so that bug does not touch us. On the pub side most direct deps are a major behind
  and get dragged forward: `flutter_bloc` 8→9, `web_socket_channel` 2→3, `connectivity_plus` 5→6+,
  `flutter_local_notifications` 17→19+, `share_plus` 10→11, `get_it` 7→8, `freezed` 2→3,
  `flutter_lints` 3→6, plus `flutter_sound` 9.x which `pubspec.yaml` already flags as debt.
- **Does the app need anything in those releases? No.** No fix matching a bug we have, no
  audio/recording fix for our stack, no security advisory. Under the standing policy — upgrade only
  when something breaks or something needed requires it — there is no compelling reason.

## How to check versions yourself

```bash
./flutter.sh --version            # the vendored SDK (this repo)
flutter --version                 # the laptop's own install — will differ
flutter upgrade --verify-only     # shows what is available, changes nothing
flutter doctor -v                 # shows which JDK Flutter resolved
flutter analyze --suggestions     # Flutter's own Java/Gradle/AGP compatibility report
```

The repo's `flutter/` is excluded from the laptop rsync, so the first two commands answer about two
different SDKs. Check both before concluding anything.
