> **Headline finding (read first)**: the bundled dev server URL is `http://10.0.2.2:7999`

> For a real-device PoC you MUST repoint the app at the dev server's LAN IP (Step 0b) **or** run
> on the emulator. Doze/wake testing (Stage 2) needs a physical device; the Stage-1 PoC runs fine
> on either.

## Step 0b — Point the app at a reachable server (REAL DEVICE ONLY)

Skip this entirely if you're running on the **emulator** (10.0.2.2 already works there).

For a **physical phone** on the same Wi-Fi/LAN as the dev server, edit
`assets/config/server-contexts.json` BEFORE building. Change the `dev` context's `baseUrl`/`wsUrl`
from `10.0.2.2` to the **dev server's LAN IP** (find it on the dev box with `hostname -I` / `ip addr`):

```json
"dev": {
  "displayName": "Dev",
  "baseUrl": "http://192.168.X.Y:7999",
  "wsUrl":   "ws://192.168.X.Y:7999"
}
```

- Edit the SOURCE copy on the dev server (so it survives rsync), or edit on the laptop AFTER
  rsync but BEFORE build — either works; editing the source is cleaner.
- Phone and dev server must be on the same network; the dev server's `:7999` must be reachable
  from the phone (test from the phone's browser: `http://192.168.X.Y:7999/docs`).
- Alternative (advanced): `adb reverse tcp:7999 tcp:7999` tunnels the phone's loopback to the
  laptop — but only helps if the SERVER runs on the laptop, which it does not here. LAN-IP repoint
  is the correct path for this setup. (Config read path: `server_context_service.dart:48-75` loads
  the bundled JSON and applies `baseUrl`/`wsUrl` to `AppConstants`.)

## Step 1 — Build + deploy (one command)

```bash
cd ~/Projects/lupin-mobile/src/scripts   # or /Volumes/.../src/scripts
./build-and-deploy-lupin-mobile.sh
```

That runs rsync (`--write --yes`) → `flutter pub get` → `flutter build apk --debug` →
`adb install -r` → launch `ai.deepily.lupin_mobile/.MainActivity` → filtered logcat (Ctrl+C to stop).

**Do NOT pass `--dart-define=ENABLE_FCM=true`.** The PoC needs no Firebase. With the flag OFF
(default), `initFcmIfEnabled()` is a no-op (`fcm_bootstrap.dart:41,61`). Passing it true would try
to init Firebase and fail for lack of `google-services.json` — exactly the work this PoC avoids.

**Optional — prefill the debug login** (saves typing credentials each launch; debug-only,
`kDebugMode`-gated, never in release):
```bash
export LUPIN_DEV_EMAIL="you@example.com"
export LUPIN_DEV_PASSWORD="…"
./build-and-deploy-lupin-mobile.sh      # script bakes these via --dart-define
```

**Manual equivalent** (if you prefer step-by-step):
```bash
./rsync-lupin-mobile.sh --write --yes
cd ~/Projects/lupin-mobile
flutter pub get
flutter build apk --debug
adb install -r build/app/outputs/flutter-apk/app-debug.apk
adb shell am start -n ai.deepily.lupin_mobile/ai.deepily.lupin_mobile.MainActivity
```

## Step 2 — First-launch checklist (on the device)

1. **Log in** (or confirm the prefilled creds) — auth is a Bearer token to the dev server.
2. **Grant the microphone permission** when prompted (needed for S4 voice replies; `record` +
   `permission_handler`). Deny → voice reply shows the permission-guidance affordance, the rest
   of the surface still works.
3. **WebSocket connects** — watch logcat for the queue WS auth handshake; the focus surface
   populates from live session notifications.
4. **Focus surface should show**: the vertical **session badge rail** (establishment order), the
   active conversation's last messages, serial **TTS with pause/resume** (incoming notifications
   speak one at a time; pause holds, resume continues), and a **voice-reply** field (mic →
   transcribe → review → send).

## Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| App loads but no data / WS won't connect (physical phone) | still pointed at `10.0.2.2` | Step 0b — repoint to dev server LAN IP; verify `http://<ip>:7999/docs` from the phone browser |
| `No adb devices found` | device not connected / USB-debug off / emulator not started | physical: enable USB debugging; emulator: start it first (`emu` alias) |
| Gradle build fails on `java.time` / desugaring | desugaring misconfigured | already set at `build.gradle.kts:53`; ensure laptop Flutter pulled deps (`flutter pub get`) |
| Mic permission denied, voice reply dead | runtime permission | grant in Settings → Apps → Lupin Mobile → Permissions, or re-prompt |
| Firebase / google-services error at boot | `ENABLE_FCM=true` passed by mistake | rebuild WITHOUT the dart-define; PoC must run flag-OFF |
| `pub get` resolves odd versions | stale lock on laptop | the rsync excludes `.dart_tool/`; `flutter pub get` regenerates — safe |

## Findings summary (for the record)

- **Scripts existed**: both `rsync-lupin-mobile.sh` and the one-command
  `build-and-deploy-lupin-mobile.sh` — this runbook wraps them, supplying only Step 0b (real-device
  reachability) and the FCM-OFF guidance they don't cover.
- **Server reachability**: app reads `assets/config/server-contexts.json` (default `dev`) via
  `server_context_service.dart:48-75` → `AppConstants.apiBaseUrl/wsBaseUrl`. Bundled dev =
  `10.0.2.2:7999` (emulator-only alias). **Real device needs the LAN-IP repoint** — the single
  gotcha that would otherwise silently break a phone PoC.
- **No real blocker** to the Stage-1 PoC build: minSdk/desugaring configured, FCM cleanly
  flag-gated OFF, deploy script proven. The only required human judgment is the Step 0b server IP.
