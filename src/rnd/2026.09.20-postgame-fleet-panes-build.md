## 2. The number that should change how this fleet tests

Chloé ran four mutation arms against her finished pane. Arm C — pointing the cap dial's `onSetCap` at the wrong event — **killed 4 tests while 22 stayed green**, every pane and bloc test among them.

Three separate test files *looked* like they covered that dial. The pane test supplied its own callback. The bloc test supplied its own repository. The screen test swapped the repository out. **Each proved one half while handing in the other.**

⇒ Unit tests on either side of a seam are **structurally incapable** of failing on the seam. Not unlikely to — incapable. You can add a hundred tests to either side and never catch it.

**The control**: drive a real tap through the real widget tree, substitute nothing above the socket, and assert the request that actually went out. Chloé's seam test swaps only the HTTP adapter for a recorder.

## 3. One defect family, three faces, and it ran in both directions

| Face | Who | Direction |
|---|---|---|
| A guard scanned source for `"TaskRow("`, which also matches `"FinishedTaskRow("` | **Sam's guard** (Phase 0, `24715f2`) + **Rachel's class name** (Phase 2); Tiffany merged them red | **false alarm** |

All three are the same root: **the instrument matched or measured something other than what its author believed.**

⚠️ **The first row was misattributed in this document's first draft, and Sam corrected it with `git log --follow`.** Verified: the guard is his, introduced in Phase 0 at `24715f2`, and absent from Rachel's Phase 2 tree. That correction makes the case *stronger*, not weaker — **neither seat's code was wrong on its own.** Sam's guard was correct against the code that existed when he wrote it. Rachel's `FinishedTaskRow` was a reasonable name for her own row. **The defect existed only in the union, created by the merge, owned by neither author.**

⇒ Which is the entire argument of §7: a defect that belongs to the merge is invisible to everyone watching a branch, and no amount of care by either author would have prevented it.

⇒ **The comfort direction is the dangerous one, because nobody investigates good news.** A seat seeing green with less coverage than the main tree has no reason to look.

⇒ Sam's line, which is the keeper: **a worktree that reports different results from the main tree is a measuring instrument that changes the thing it measures, which is worse than either specific bug.**

## 4. A green test is evidence only if it could have been red

Arrived at independently, three times in one evening, by three people:

- **Rachel** wrote a meta-test that renders a `TaskRow` to prove her negative guard could still catch one — because a rename in another phase would leave a guard that passes by matching nothing.
- **Tiffany** demanded a `git diff` instead of an assurance when a shared-base divergence was suspected, and got `--name-only` returning empty as the answer.
- **Sam** reverted his fix to the exact original defect, watched the tests go red, and restored it: *"a test written to catch a defect you have already fixed is a test nobody has ever seen fail."*

**Now standing practice**: any test written against a known defect gets the defect reintroduced once, observed red, then restored. Watch the ceiling as well as the floor — a near-total kill is a syntax error wearing a finding's clothes.

## 5. Fixtures are captured, never authored

An authored fixture agrees with itself. It cannot contradict the producer, because the producer was never consulted.

Chloé's capture of live fleet state contained a row with a window size and a **null** consumption percentage — two columns the design doc treated as one. A hand-written fixture would have moved both together, **the test would have passed, and it would have been asserting something false.** It failed on her first run.

Sam's counter-example completes the rule: his authored fixture manufactured a **false red** and a false defect report. **The direction of the lie is not something the author gets to choose.**

## 7. Controls installed, not intentions recorded

Rachel's reframe when the manager offered an account of the red-test miss: *"that guard fired the moment it merged and nobody read the number, so the control that would have caught it is running the suite on the merge result, not on the branch."*

⇒ **A rule that depends on a reviewer noticing is not installed.** The manager's version blamed attention; hers names something you can run.

**Installed tonight:**
- The suite runs on the **merge result**, not the branch. A merge is a change nobody tested.
- Widget tests render at **360×800**, never the 800×600 harness default — an overflow invisible on the default breaks every real phone.
- Exclusions carry a **measured number**, not a category name. *"Generated code"* ends an argument; *"hides 7744, none ours"* invites one. An exclusion that hides nothing is not free.

  ⇒ **Three of the four proposed patterns matched zero files**, and the count decided each one differently. `*.g.dart` and `*.freezed.dart` were **dropped** — this repo has no generated Dart at all, so they told a future reader something untrue about the codebase. `build/**` was **kept** on the same zero count, because a build run can drop Dart there at any time and the finding would be un-actionable when it does. Only `flutter/**` had a real number: **7744**.

  ⇒ Same measurement, opposite verdicts, and that is the point — **the number does not decide for you, it lets you decide in the open.** The final file says `build/**` currently hides zero *in its own comment*, which is harder than deleting it and more useful than a silent justification.
- Cite source by **content**, not line number — in a file with near-duplicates, a drifted citation lands on a look-alike and **reads as confirmation**.

## 8. Process notes worth keeping

- **Gates were not gamed, twice.** The ticket gate offers a P0 exemption; the create gate refuses live status below P0. Honest P1/P2 rows stayed P1/P2, and content went to `task_amend` and the committed doc instead. A control relabelled around stops meaning anything.
- **The DM condenser mangled at least four messages** — two turned a third-party mention into a salutation, one dropped a decision question entirely, one stripped the owner off a defect report. **Put decisions in the first two lines; the summarizer drops the tail first.** Verify names and ids against the store, never against a DM.
- **A context reading is a coordinate, not a reference.** One warning predated the seat's own `/clear` and would have cost a pointless re-spin.
- **Use the verb that owns the invariants.** A raw write to a managed file lands correct bytes beside a stale mirror and a stale pointer. The failure is invisible at the moment you make it — the same shape as *a copy does not merge, it replaces.*
