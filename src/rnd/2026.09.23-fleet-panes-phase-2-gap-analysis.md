## 3. What the plan needs before the build (the only planning work)

a. **The per-row reason input on a phone (G1, G5).** The plan specifies each verb's payload (§4.3) and arm-then-confirm (§7.4). It doesn't say where a phone user types a per-row reason or the `fixed` attestation. **Proposal:** a bottom sheet opened from the row's verb, with the reason box and each verb's own complaint text (§4.3 point 4). *Needs Tiffany's call; not a Rick ruling.*
b. **Task List ordering.** The code sorts by priority, then status, per Rick's ruling of 09-09, and drops terminal rows. The plan (§8.3) still says status, then priority. **Amend the plan to match the ruling.**
c. **Broadcast reconciliation (§6.2).** The mobile code correctly refuses the `/undelivered` drain because acks never reach that store. Rick ruled on 09-23 on lupin row `1c7da903`: acks are saved with notifications, with `payload.broadcast_id`. **Rewrite §6.2 and Appendix A #6 against that new contract.** The mobile half waits until the server half lands.

d. **Plan §8.5, "a count, not a picker," is overruled by Rick's own words on hardware (W2).** Amend it to a recipient list with "all". Tiffany's walkthrough plan already has a section on this.
e. **G5, per-row verbs in the Holding Area, was left out on purpose for now** (Tiffany). They'll arrive with **one shared reason-sheet widget** that serves both task panes, which is also §3a's answer. Build that widget once and G1 and G5 both close.
